# Что можно сделать дальше

Ничего из этого списка не начато. Порядок примерный.

## Скиллы

- **Доска.** Один скилл с описанием каждого вида: когда нужен, как пишутся стикеры, шаблон сцены, чек-лист проверки. Его вызывают `grilling`, `domain-modeling` и `wayfinder`, когда нужно показать.
- **Разбор процесса.** Как агент ведёт EventStorming в переписке: собрать принятое, пройти процесс по шагам, вынести детали списком, существенное задать вопросами, записать итог.
- **Общая картина и границы.** Лента событий всей области, поддомены, карта контекстов.
- **Примеры.** Example Mapping для спорных правил и перенос примеров в тесты.

Инструкции для скиллов пишутся на английском, тексты для людей на языке проекта.

## Инструмент доски

- Сохранять правки из браузера обратно в файл сцены.
- Экспорт кадров без встроенного браузера Orca, например через Playwright.
- Скрипт, который собирает из файла сцены таблицы шагов и список примеров для итога задачи. Сейчас это разовые скрипты сессии.
- Автоматическая публикация галереи при изменении доски и сборка одной страницы из нескольких веток `design/*`. Вручную публикация через GitHub Pages уже проверена на `ai-first-platform`.
- Шаблоны сцен для видов «Общая картина» и «Карта». Сейчас есть процесс, жизненный цикл, примеры и техническая карта вызовов.
- Доступ агента к доске через MCP для клиентов без встроенного браузера.
- Проверить перетаскивание групп и поведение на системе без шрифта Helvetica.

## Чего не хватает для уверенности

- Набор проверен на одной сессии одного проекта.
- Виды «Общая картина» и «Карта» описаны, но ни разу не нарисованы. Вид «Проектирование» нарисован только как карта вызовов между модулями.
- Не проверено, справится ли со сценой более слабая модель по одному описанию.
