# Доска

Доска нужна, когда вопрос про порядок, связи или границы. Цели, требования и список задач понятнее в тексте и таблицах.

## Виды

Один вид отвечает на один вопрос.

| Вид | На какой вопрос отвечает | Когда нужен |
|---|---|---|
| Общая картина | Как устроена вся область, где границы | Новый продукт или большая область |
| Карта | Кто владеет какими данными, какие есть контексты и внешние системы | Несколько модулей или внешних систем |
| Процесс | Кто что делает, что происходит, какие правила | Фича с несколькими шагами или участниками |
| Жизненный цикл | В каких состояниях бывает объект, какие переходы запрещены | У объекта три и больше состояний |
| Примеры | Что должно получиться в конкретном спорном случае | Гонки, повторы, границы, всё, что станет тестом |
| Проектирование | Как правила лягут в код: агрегаты, вызовы, события | Сложная основная логика |

## Одна доска или несколько

Одна доска держит один предмет с одним сроком жизни. Внутри доски каждый вид занимает свой кадр.

| Доска | Какие кадры | Сколько живёт |
|---|---|---|
| Доска продукта | Общая картина, карта | Долго, меняется редко |
| Доска части продукта | Процессы, жизненные циклы, примеры, открытые вопросы | Вместе со спецификацией. После реализации это история |
| Доска технического решения | Проектирование, техническая карта вызовов | До конца реализации |
| Доска беседы | Любые | Временная |

Доску пора делить, если на ней больше восьми кадров, кадры разного уровня или у кадров разные читатели. Домен и технику держим на разных досках.

## Нотация

Нотация взята из EventStorming.

| Стикер | Цвет | Как пишем |
|---|---|---|
| Действие | Синий | Повелительное наклонение: «Принять приглашение». Номер шага стоит только здесь |
| Событие | Оранжевый | Прошедшее время: «Приглашение принято» |
| Событие побочной ветки | Бледно-оранжевый | Отказ или ошибка: «Принятие отклонено» |
| Участник | Жёлтая метка под действием | Роль, а не имя человека |
| Данные модуля | Бледно-жёлтый | Существительное из глоссария. В EventStorming это агрегат |
| Реакция | Сиреневый | «Когда X»: за ней идёт действие, которое система делает сама |
| Внешняя система | Розовый | Название системы |
| Что видит участник | Зелёный | Сведения, по которым участник принимает решение |
| Правило | Карточка с фиолетовой рамкой | Заголовок называет шаг: «Шаг 2». Внутри пункты |
| Открытый вопрос | Красная метка на шаге и красная карточка | Номер H1, H2 и короткое название |

- Сплошная рамка значит «принято». Пунктирная значит «предложено, ждёт решения».
- Сплошная стрелка показывает порядок шагов, чтение или проверку. Оранжевая пунктирная показывает событие между модулями.
- На стикерах стоят только слова из глоссария. Модули подписаны в виде «English / русский».
- На доске свои номера: шаги внутри блока, H для открытых вопросов, P для предложений. Номеров из переписки на доске нет.

## Раскладка

- Дорожки показывают владельца данных. В разделе есть только занятые дорожки.
- Один стикер держит одно понятие. Одно действие ведёт к одному событию по прямой линии.
- Общие данные рисуются одним высоким стикером через несколько строк.
- Участник прикреплён к своему действию. Отдельной дорожки участников нет.
- Длинный процесс делится на разделы с подзаголовками. Раздел не шире шести-семи колонок.
- Следующий раздел начинается с события, которым закончился предыдущий.
- Стрелка прямая или с одним изгибом. Она не идёт вдоль рамки стикера и не проходит сквозь стикеры.
- Зазоры между стикерами одинаковые. Подпись стоит рядом с линией и не разрывает её.
- Размер стикера считается по тексту. Продолжение пункта переносится с отступом.
- Правила и открытые вопросы стоят в колонке справа от раздела.
- Заголовок кадра написан текстом внутри кадра.

## Проверка перед показом

Сними скриншот каждого кадра в масштабе, при котором читается текст, и ищи:

1. Текст наезжает на текст, линию или рамку.
2. Текст обрезан или упирается в край стикера.
3. Стрелка идёт вплотную к чужому стикеру и кажется связанной с ним.
4. Стрелка без начала или без конца, подпись закрывает линию.
5. Стикер стоит на чужой дорожке.
6. Правило или вопрос не привязаны к шагу.
7. Пустые дорожки и раздел, который не помещается на экран.
8. Цвет, которого нет в легенде. Два почти одинаковых цвета.
9. Слова не из глоссария, номера из переписки, номера задач без названия.
10. Не видно, что принято, а что только предложено.

## Примеры на доске и в тексте

Примеры состоят из текста, поэтому их основное место в итоге задачи или спецификации: оттуда их берут тесты.

- Во время обсуждения кадр «Примеры» держит правило и его случаи рядом с процессом.
- В итоговом снимке доски остаются случаи про гонки и открытые вопросы. Полный список идёт в текст.
- Процессы по шагам тоже записываются текстом: таблица «шаг, кто, действие, данные и владелец, что получается». Агент доску не читает, поэтому без таблицы он не увидит порядка шагов и названий событий.

## Как хранится

- Исходник доски лежит файлом сцены в ветке `design/<спецификация>`, которая не сливается в `main`.
- Каждый кадр сохраняется картинкой PNG со сценой внутри. Итог задачи показывает картинки по постоянной ссылке на ревизию.
- Страница [`gallery/index.html`](../gallery/index.html) показывает все доски ветки: описание, ссылку на интерактивную доску и кадры.

## Как посмотреть без запуска

Страница доски загружает соседние скрипты, а браузер не разрешает это для файла, открытого с диска. Поэтому доске нужен веб-сервер. Чтобы ничего не запускать, папку с досками публикуют на хостинге статических сайтов.

Для репозитория на GitHub это GitHub Pages:

1. Создай ветку `gh-pages`, в корне которой лежит содержимое папки `design` и пустой файл `.nojekyll`.
2. Отправь её на GitHub. Для публичного репозитория Pages включается сам, сайт открывается по адресу `https://<владелец>.github.io/<репозиторий>/`.
3. После изменения доски заново экспортируй кадры и обнови ветку `gh-pages` копией папки `design`.

Сайт публичный. Для закрытого репозитория нужен платный тариф GitHub или другой хостинг с доступом по входу.
- Доска не хранит решения. Всё принятое записано текстом по [storage.md](storage.md).

## Инструмент

[`board/kit.js`](../board/kit.js) раскладывает сцену для Excalidraw, сцена описывает только содержание.

| Функция | Что рисует |
|---|---|
| `frame` | Кадр с заголовком внутри |
| `section` | Раздел: подзаголовок, дорожки и сетка. `at(lane, col, row)` даёт центр ячейки, `panel` ставит карточки справа |
| `sticky` | Стикер в ячейке, высота растёт по тексту |
| `span` | Стикер на несколько ячеек: высокие данные или широкая полоса |
| `chip` | Метка на стикере: участник снизу, открытый вопрос сверху |
| `arrow` | Стрелка между стикерами: прямая или с одним изгибом |
| `path` | Стрелка по точкам с подписью рядом |
| `stack`, `card` | Карточки правил, вопросов, предложений и примеров |
| `titled` | Блок с заголовком и списком, например модуль на карте |

Примеры сцен: [доска поведения](../board/examples/spec48/scene.js) и [техническая доска](../board/examples/spec48/technical.scene.js) одной спецификации.

Сверху доски стоит текст: что это за доска, чего на ней нет, как её читать и в каком она состоянии.

Что пока не работает:

- Правки, сделанные в браузере, не сохраняются в файл сцены.
- Экспорт кадров работает через помощник `window.__exportFrame` на странице и скрипт [`export_frames.py`](../board/export_frames.py), которому нужен встроенный браузер Orca.
- Перетаскивание групп не проверено.
- Ширина текста измеряется шрифтом Helvetica. На системе без него размеры стикеров могут не совпасть.
