# Domain guidance

Before domain design or exploration, read `DOMAIN.md` for canonical terms.
Read relevant ADRs under `docs/adr/` when they exist.
This repository currently has one context and no required ADR directory.
Create domain artifacts only when there is a resolved term or a consequential accepted trade-off.
Use `domain-modeling` for active glossary and ADR work.
Keep implementation details and task plans outside the glossary.
